## Description / توضیح پروژه

این متن انگلیسی را در فرم وارد کن:

```text
Lingora is an open-source desktop application and browser extension that translates live audio and uploaded media, presents synchronized original and translated subtitles, and can generate translated speech. Processing starts only when the user selects a source, and users provide their own supported AI-service credentials.
```

معادل طبیعی فارسی:

## نکات مهم پیش از ارسال

- SignPath می‌خواهد جست‌وجوی Google پروژه را به‌وضوح پیدا کند. چون نام `Lingora` در نتایج دیگری هم دیده می‌شود، مقدار دقیق‌تر `Lingora Live Translator` برای فرم مناسب‌تر است؛ نام محصول همچنان Lingora باقی می‌ماند.
- مخزن تازه است و هنوز شاهد مستقلی از استفادهٔ گسترده ندارد. SignPath حد عددی عمومی اعلام نکرده و پذیرش را موردی بررسی می‌کند. کاربر واقعی، دانلود، Star، گفت‌وگوی جامعه یا معرفی مستقل، شانس پذیرش را بیشتر می‌کند.
- تأیید دومرحله‌ای GitHub و SignPath باید روشن باشد.
- اطلاعات نام، ایمیل و وابستگی سازمانی را پیش از ارسال نهایی تأیید کن. نام دانشگاه را فقط زمانی وارد کن که واقعاً می‌خواهی و مجاز هستی آن وابستگی را اعلام کنی.

## الزامات عمومی که در مخزن آماده شده‌اند

README و گردش‌کار Release عنوان **Code signing policy** و جملهٔ الزامی زیر را دارند:

> Free code signing provided by SignPath.io, certificate by SignPath Foundation

سند مرجع [CODE_SIGNING_POLICY.md](../CODE_SIGNING_POLICY.md) نقش‌های Committer/Reviewer و Release Approver، سیاست حریم خصوصی، قواعد Origin، تأیید دستی و دستور بررسی امضا را مشخص کرده است. نصب‌کنندهٔ Windows پیش از نصب `PRIVACY.md` را نشان می‌دهد و Uninstaller استاندارد دارد.

## کارهایی که پس از پذیرش SignPath انجام می‌شوند

1. در صورت درخواست SignPath، GitHub App آن را فقط برای مخزن `msmahdinejad/lingora` نصب و تأیید کن.
2. GitHub.com را به‌عنوان Trusted Build System اضافه و مخزن را متصل کن.
3. Project و Release signing policy را با Origin verification و تأیید دستی اجباری بساز.
4. یک `Lingora-Setup-x64.exe` واقعی و امضانشده را به‌عنوان Artifact داخلی بارگذاری و تنظیمات آن را با [`.signpath/artifact-configuration.xml`](../.signpath/artifact-configuration.xml) اعتبارسنجی کن.
5. یک توکن جداگانه با نقش Submitter بساز.
6. Secret مخزن با نام `SIGNPATH_API_TOKEN` را اضافه کن.
7. این Repository variables را با مقادیر واقعی پنل SignPath بساز:
   - `SIGNPATH_ENABLED=true`
   - `SIGNPATH_ORGANIZATION_ID=<assigned organization id>`
   - `SIGNPATH_PROJECT_SLUG=<assigned project slug>`
   - `SIGNPATH_SIGNING_POLICY_SLUG=<assigned release policy slug>`
   - `SIGNPATH_ARTIFACT_CONFIGURATION_SLUG=<assigned artifact configuration slug>`
8. یک Tag بازبینی‌شده با الگوی `vMAJOR.MINOR.PATCH` Push کن. Workflow فایل امضانشده را فقط به‌عنوان Artifact داخلی می‌فرستد، منتظر SignPath می‌ماند، امضای برگشتی را محلی بررسی می‌کند و فقط نسخهٔ امضاشده را منتشر می‌کند.
9. روی یک سیستم Windows تمیز این دو دستور را اجرا کن:

```powershell
Get-AuthenticodeSignature .\Lingora-Setup-x64.exe | Format-List Status,StatusMessage,SignerCertificate,TimeStamperCertificate
Get-FileHash .\Lingora-Setup-x64.exe -Algorithm SHA256
```

تا وقتی `SIGNPATH_ENABLED=true` تنظیم نشده باشد، Workflow نصب‌کنندهٔ امضانشده را پیش از انتشار حذف می‌کند. خروجی‌های ZIP سیستم‌عامل‌ها و اکستنشن می‌توانند منتشر شوند، اما نصب‌کنندهٔ نهایی Windows بدون امضا در Release عمومی قرار نمی‌گیرد.
