## دو محصول مستقل

فقط چیزی را نصب کن که استفاده می‌کنی:

- **تب مرورگر:** Chrome/Edge 116+، فایل ZIP اکستنشن و Gemini API Key؛ اپ ویندوز لازم نیست.
- **برنامه‌های دسکتاپ:** Windows 10/11 x64، اپ ویندوز، Gemini API Key و معمولاً Virtual Cable.
- **شبکه:** اپ فیلد پروکسی خودش را دارد؛ اکستنشن از تنظیم Proxy خود Chrome/Edge یا سیستم استفاده می‌کند.

## نصب Companion

1. `LingoDub-Setup-x64.exe` را از Releases دانلود و نصب کن.
2. برنامه را اجرا کن؛ داشبورد خودکار باز می‌شود.
3. از تنظیمات پیشرفته، API Key را وارد و ذخیره کن.
4. آدرس پروکسی را تنظیم کن؛ برای اتصال مستقیم خالی بگذار.

کلید در Windows Credential Manager ذخیره می‌شود و داخل `settings.json` نیست. توسعه‌دهنده‌ها می‌توانند از `.env` هم استفاده کنند؛ این فایل وارد Git نمی‌شود.

## نصب اکستنشن مستقل

1. `LingoDub-Extension.zip` را دانلود و در یک مسیر ثابت Extract کن؛ خود فایل ZIP را انتخاب نکن.
2. `chrome://extensions` یا `edge://extensions` را باز کن.
3. **Developer mode** را روشن کن.
4. **Load unpacked** را بزن و پوشه‌ای را انتخاب کن که `manifest.json` مستقیماً داخل آن است.
5. اکستنشن را Pin و Popup آن را باز کن.
6. Gemini API Key خودت را وارد و برای نشست فعلی مرورگر ذخیره کن.
7. تب ویدیو را باز کن و «شروع دوبلهٔ این تب» را بزن.

هیچ اپ، سرویس localhost، Virtual Cable یا Python لازم نیست. اکستنشن فقط تبی را Capture می‌کند که خودت Start زده‌ای، مستقیم به Gemini وصل می‌شود و صدا را مطابق حالت انتخابی بازسازی می‌کند؛ بنابراین «فقط دوبله» با صدای اصلی هم‌پوشانی ندارد.

کلید عمداً در `chrome.storage.session` می‌ماند: Sync نمی‌شود و بعد از بسته‌شدن کامل Chrome/Edge باید دوباره وارد شود. تنظیمات عادی محلی باقی می‌مانند. اگر ضبط روشن باشد، پس از Stop چهار فایل `original.wav`، `source.srt`، `dubbed.wav` و `translated.srt` در Downloads ساخته می‌شوند.

### پروکسی اکستنشن مستقل

WebSocket جاوااسکریپت نمی‌تواند Proxy اختصاصی برای هر درخواست انتخاب کند. اکستنشن از Proxy مرورگر/سیستم استفاده می‌کند. اگر سرویس تو روی `127.0.0.1:10808` است، در کلاینت Proxy حالت System Proxy را روشن کن یا Chrome/Edge را از همان Proxy عبور بده. فیلد Proxy داخل اپ ویندوز فقط روی خود اپ اثر دارد.

در نسخهٔ Cloneشده، [`install-extension.cmd`](../install-extension.cmd) هنوز پوشهٔ ثابت را آماده می‌کند. نصب‌کنندهٔ اپ ویندوز عمداً دیگر اکستنشن را کپی یا تنظیم نمی‌کند.

### چرا نصب مستقیم یک‌کلیکی از GitHub نداریم؟

[Chrome در Windows و macOS فقط اکستنشن میزبانی و امضاشده در Chrome Web Store را مستقیم نصب می‌کند](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions). فایل CRX محلی یا دانلود GitHub اجازهٔ نصب مخفی ندارد. برای دکمهٔ واقعی **Add to Chrome** باید LingoDub در Chrome Web Store منتشر و بررسی شود؛ Edge نیز فهرست جداگانه در Microsoft Edge Add-ons می‌خواهد. سازمان‌ها می‌توانند از policyهای مدیریتی استفاده کنند.

قبل از ارسال، [چک‌لیست به‌روز Chrome Web Store](CHROME_WEB_STORE.md) و [سیاست حریم خصوصی](../PRIVACY.md) را ببین.

## تنظیم دستی صدای برنامه‌های ویندوز

برنامه‌ای مثل VLC صدایش را مستقیم به خروجی ویندوز می‌فرستد. برای جداسازی آن:

> **این مراحل فقط برای برنامه‌های دسکتاپ است. هنگام استفاده از اکستنشن، خروجی Chrome/Edge را تغییر نده و تمام این بخش را رد کن.**

### مسیر صحیح صدا

```text
خروجی VLC یا برنامهٔ منبع → CABLE Input → ورودی Loopback داخل LingoDub
خروجی شنیداری LingoDub → هدفون یا اسپیکر واقعی
```

### مراحل دقیق

1. یک Virtual Audio Device معتبر مثل [نسخهٔ رسمی VB-CABLE](https://vb-audio.com/Cable/) نصب کن یا از نمونهٔ مشابه فعلی استفاده کن. اگر نصب‌کننده خواست، Windows را Restart کن.
2. VLC، برنامهٔ دوره یا Player را باز و چند ثانیه صدا پخش کن؛ Windows معمولاً برنامه را بعد از شروع Audio Session داخل Volume Mixer نشان می‌دهد.
3. مسیر **Settings → System → Sound → Volume mixer** را باز کن. دکمهٔ «باز کردن میکسر صدای ویندوز» در داشبورد مستقیم همین صفحه را باز می‌کند. [Microsoft نیز انتخاب خروجی اختصاصی هر برنامه را از همین بخش توضیح می‌دهد](https://support.microsoft.com/en-US/Windows/Hardware/audio/fix-app-audio-not-working-while-system-sounds-work-in-windows).
4. زیر بخش **Apps**، برنامهٔ منبع را پیدا و **Output device** آن را روی `CABLE Input (VB-Audio Virtual Cable)` یا خروجی مجازی مشابه بگذار.
5. داخل LingoDub، «ورودی صدای برنامه» را Loopback همان کابل انتخاب کن؛ نام آن معمولاً شبیه `CABLE Input ... [Loopback]` است.
6. «خروجی شنیداری» LingoDub را هدفون یا اسپیکر واقعی قرار بده.
7. صدای اصلی را ۰٪ و دوبله را ۱۰۰٪ بگذار، تنظیمات را ذخیره و دوبله را شروع کن.

![راهنمای مسیر صدای دسکتاپ](images/audio-routing-guide.png)

### نتیجهٔ درست

- پیش از شروع LingoDub ممکن است صدای برنامهٔ منبع قطع شود؛ چون خروجی آن اکنون به Virtual Cable می‌رود.
- بعد از اتصال LingoDub، صدای ترجمه از هدفون یا اسپیکر واقعی پخش می‌شود.
- اگر صدای اصلی را بیشتر از ۰٪ بگذاری، LingoDub عمداً آن را با دوبله ترکیب می‌کند.

نصب Driver یا تغییر خروجی یک برنامهٔ دیگر دیگر «خودکار» معرفی نمی‌شود. نصب درایور به دسترسی Administrator و تأیید اعتماد نیاز دارد و مسیر خروجی هر برنامه به‌صورت قابل‌اعتماد از Windows Volume Mixer کنترل می‌شود. LingoDub صفحهٔ درست را باز می‌کند و انتخاب ورودی/خروجی خودش را شفاف و دستی نگه می‌دارد.

## رفع مشکل

- **اکستنشن دوباره Key می‌خواهد:** بعد از بسته‌شدن کامل مرورگر طبیعی است؛ کلید عمداً Session-only است.
- **اکستنشن وصل نمی‌شود:** دسترسی مدل و سهمیه را بررسی کن و مطمئن شو خود Chrome/Edge از Proxy لازم عبور می‌کند؛ Proxy اپ روی اکستنشن اثری ندارد.
- **اپ دسکتاپ آفلاین است:** `LingoDub.exe` را اجرا کن.
- **ترجمه نمی‌آید:** Key، دسترسی مدل، سهمیه و Proxy همان محصول را بررسی کن.
- **صدای تب نمی‌آید:** نسخهٔ مرورگر حداقل ۱۱۶ باشد و هنگام Start همان تب فعال باشد. صفحات DRM ممکن است Capture را مسدود کنند.
- **برنامه در Volume Mixer دیده نمی‌شود:** اول داخل همان برنامه صدا پخش کن و بعد Volume Mixer را دوباره باز کن.
- **صدای اصلی برنامه هنوز مستقیم شنیده می‌شود:** خروجی آن برنامه هنوز روی هدفون است؛ آن را روی `CABLE Input` بگذار.
- **LingoDub صدای برنامه را دریافت نمی‌کند:** ورودی صدای برنامه را Loopback کابل مجازی انتخاب کن، نه میکروفون.
- **Echo در برنامهٔ دسکتاپ:** ورودی Capture و خروجی دوبله نباید یک Device باشند.
- **گویندهٔ انتخابی تأخیر دارد:** گوینده‌های نام‌دار یک مرحلهٔ TTS اضافه دارند؛ برای کمترین تأخیر `Native` را بگذار.
